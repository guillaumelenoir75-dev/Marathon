# Plan Marathon — contexte projet

PWA de préparation marathon, multi-utilisateur. L'admin crée les comptes et a accès au Coach IA. Les athlètes suivent leur plan.

## Stack
- **Frontend** : `public/index.html` — HTML + CSS inline, charge 23 scripts JS via `<script defer>`.  
  Build : Vite (`root: 'public'`, `publicDir: '../public-static'`) → `dist/`. Les fichiers `public-static/src/*.js` sont copiés verbatim (pas de hash), chargés en scripts classiques (pas de modules ES). Toutes les fonctions doivent être en scope global.
  **Chargement** : `scriptFiles` (vite.config.js) → un seul `bundle-<n°>.js` ; écrans rares → `lazy-<groupe>-<n°>.js` (`lazyGroups` : `course` = race-nav-data + race-nav + race-map, `progress` = prep-progress, `whatif` = plan-whatif, `nextrace` = next-race, `planchat` = plan-chat, `season` = season, `renfo` = renfo-guide ; écrans rares sortis des gros fichiers (`*-ui.js`) : `predict` = predict-ui (fenêtres de prédiction), `review` = plan-review-ui (MAJ le plan, Mes records), `share` = week-share-ui (images à partager), `charts` = body-signals-ui (niveau, allures, ta nuit, données à vérifier), `alcui` = alcohol-ui (détail Alcool), `raui` = race-analysis-ui (analyse de course), `voice` = coach-voice (parler au Coach), `cquality` = coach-quality-ui (Qualité du Coach), `selftest` = selftest-ui (Tester l'app), `pisteui` = piste-ui (détail de la forme du jour, Piste de nuit), `sdui` = session-lib-ui (détail d'une séance, profil de coureur, bibliothèque, prépa version pro), `admin` = plan-admin (Administration, vue Coach sur un athlète, FC max, export — `_adminPreviewUid` / `_adminPreviewName` déclarés dans config.js, `togglePwd` dans auth.js)), adresses dans `window.LAZY_BUNDLES` injecté dans dist/index.html, chargés par `lazyLoad(g)` (config.js) depuis des points d'entrée du même nom que la vraie fonction (`initRaceOrgMap`, `openProgress`, `openWhatIf`, `openNextRace`, `coachMode`, `coachModeInit`, `openPlanChat`, `pcSend`, `openSeason`, `openRenfoGuide`, `openMarathonPredModal`, `openDistancePredModal`, `openPlanReview`, `openRecordsModal`, `openWeekShare`, `openSessionShare`, `openSleepPlan`, `openDataQuality`, `openLevelChart`, `openPaceChart`, `openAlcoholInsights`, `openRaceAnalysis`, `openCoachVoice`, `openCoachQuality`, `openSelfTest`, `phFormOpen`, `openSessionDetail`, `openRunnerProfile`, `openLibCatalog`, `openLibPreview`, `openProfileModal`, `_refreshAthleteCoachView`, `openAthleteCoachView`, `cvRegeneratePlan`, `openRegenFromDateModal`, `adminUpdateAllPlans`, `cvDeletePlan`, `renderAthletePanel`, `openFcMaxEdit`, `deleteAthletePlan`, `exportPlanDocument` → `_lazyCall`) ; en dev, fichiers sources. Un module à la demande ne doit être appelé que sur action (jamais au démarrage) ; ses scripts ne sont pas dans index.html. **Écran rare = code à la demande** : une fenêtre ou un dessin ouvert seulement au toucher va dans un `*-ui.js` (calculs gardés dans le fichier d'origine, chargé par le moteur), avec son point d'entrée dans config.js ; les `*-ui.js` sont aussi dans `ENGINE_FILES` (recherche, tests) ; vérifié en e2e (« écrans rares chargés à la demande »). Cache (firebase.json) : `/src/@(bundle|lazy)-*.js` = 1 an `immutable` (nom unique par version), le reste de `/src` sans cache. Chart.js en `defer`.
- **Backend** : Cloud Functions Firebase v2 (Node 24), modulaires dans `functions/`.
- **Données** : Firebase Realtime Database, projet `prepa-marathon` (europe-west1). Structure : `users/{uid}/state`, `users/{uid}/role`, `users/{uid}/preps/{id}` (copie figée d'une prépa) + `users/{uid}/prep_index/{id}` (fiche : nom, date, temps, bilan), `users/{uid}/prep_next` (prépa à venir : `meta` + `state` = clés de prépa, modifiable avant son début), `_push_subscribers/{uid}`.
- **Auth** : email / mot de passe. Création de comptes réservée à l'administrateur (ADMIN_UID).
- **Hébergement** : Firebase Hosting → https://prepa-marathon.web.app
- **Sécurité DB** : règles dans `database.rules.json` — chaque user ne lit/écrit que ses propres données, l'admin peut tout lire/écrire.

**Écran Compte** (`#sc-compte`, public/index.html) rangé par thème, 5 lignes au plus par section : Mes courses (saison, prochaine course, prépas, records) · Mon entraînement (FC max, « Ce que le Coach sait de moi » (admin), chaussures, pilote, validation auto — la validation express est dans sa fenêtre ; « Mon profil » des athlètes) · Applis connectées (Strava, WHOOP, historique Strava, calendrier) · Suivi de course (admin : course en direct, puis une ligne par course suivie terminée — `liveRacesRowsRender` / `livePastRaces`, race-live.js, d'après les fiches `prep_index` à lien « Revoir » `?course=<id>`, 3 au plus, au-dessus du Marathon Seine-Eure : nom, date, temps ; fiche `openLivePastRace` : temps, allure, objectif, encouragements, lieu, km par km du rejeu, Revoir / Partager, Bilan, Corriger le temps) · Réglages (informations, préférences, thème) · Aide et outils (glossaire, export, santé de l'app, diagnostic) · Administration (admin). Nouvelle entrée = dans la section de son thème (vérifié en e2e).
